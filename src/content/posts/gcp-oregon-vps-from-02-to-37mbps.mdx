照着网传教程在 Google Cloud 上搭一台「永久免费」俄勒冈 VPS，往往会连续撞上两堵墙：

- 第一堵是**账单错觉**：教程里写着「免费层 e2-micro + 绑定运行中的公网 IP = 永久零成本」，但核对现行价格表才会发现，Google Cloud 早就不免外部 IPv4 的费用了。
- 第二堵是**吞吐落差**：在 VPS 上测到北美节点的带宽轻松跑上 170+ Mbps，可一从国内晚高峰直连，单线程下载掉到 **0.19 Mbps**，连 1080p 视频都卡成幻灯片。

先把核心结论放在最前面：在 **Standard 网络层（每月 200 GiB 免费出站）** 条件下，通过 **BBR + 缓冲区持久化调优**、叠加 **Hysteria2（UDP 443 + 端口跳跃）与 VLESS+REALITY 双协议共存**，晚高峰单线程实测可以从 **0.19 Mbps** 提到 **37.56 Mbps**（提升近 200 倍），完全脱离第三方中转；同时配好客户端分流与 DNS 防泄露，就能把一台低成本独享 VPS 用得既快又干净。

下面按「费用账 → 性能账 → 分流与防泄露 → IP 属性」四层拆开讲。

## 一、先把账算清：哪些真的免费，哪些一定会收钱

在 GCP 上选 `us-west1`（俄勒冈）、`e2-micro`（共享 2 核 / 1 GB 内存）、`30 GB` 标准永久磁盘，并把网络层级切到 **Standard Tier**（不要选默认的 Premium Tier），计算、磁盘以及**每个自然月 200 GiB 的出站流量**确实都在免费额度内。

容易被旧教程误导的地方只有一项：**外部 IPv4 地址**。

- 现行计费规则下，运行中实例绑定的外部 IPv4（无论临时还是静态）统一按 **$0.005/小时** 计费，持续开机约 **$3.60 ~ $3.72/月**。
- 新账号有 90 天 / $300 试用赠金，试用期内这笔费用直接从赠金扣除，不扣银行卡；试用期满若升级为付费账号（升级本身 0 元，且保留剩余赠金），免费层资源和每月 200 GiB 流量依然长期有效，真正需要承担的固定成本就是这笔约 26 元/月的 IPv4 费用。
- 既然运行中的静态 IP 与临时 IP 单价完全一致，直接把当前 IP 升级为**静态外部 IP**更省心，避免未来停机重启换 IP。但要记住一条红线：**不要把虚拟机停机却留着未释放的静态 IP**——闲置静态 IP 的单价会翻倍到 $0.01/小时。

另外，4K 视频的流量消耗大约在 10 ~ 15 GB/小时。建议在 GCP 控制台的「结算 → 预算和提醒」里建一条每月 $5 或 $10 的邮件告警，避免无意间刷超 200 GiB。

## 二、为什么刚建好只有 0.19 Mbps？跨洋链路的真实瓶颈

在 VPS 本机直连北美测速点能跑到 176 Mbps，说明瓶颈根本不在 `e2-micro` 的算力或机房出口，而在**国内晚高峰跨太平洋公网链路**本身。

Standard Tier 走的是普通公网路由（hot-potato），国内到美国西海岸的物理往返延迟在 160 ~ 190 ms 左右，晚高峰国际出口普遍伴随 1% ~ 5% 的丢包。在「高延迟 + 轻中度丢包」的组合下，传统 TCP 拥塞控制（尤其是默认的 CUBIC）会把每一次丢包都解读为严重拥塞，反复对半削减发送窗口，吞吐迅速塌缩。

我们以「测基线 → 改一项 → 复测」的方式，在同一晚高峰时段对 25 MB 下载做了一轮完整对照：

| 阶段 | 传输协议与拥塞控制 | 首字节延迟 (TTFB) | 晚高峰单线程实测 |
| --- | --- | --- | --- |
| 初始基线 | VLESS + REALITY + TCP CUBIC | — | ~0.19 Mbps |
| 临时切算法 | VLESS + REALITY + 临时 BBR | — | 0.64 ~ 1.55 Mbps |
| 内核参数调优 | VLESS + REALITY + 持久化 BBR + 16 MB 缓冲区 | 1.61 s | 1.71 Mbps |
| 切入 QUIC | Hysteria2（UDP 443 单端口） | 0.71 s | 34.94 Mbps |
| 叠加端口跳跃 | Hysteria2（UDP 20000-50000 转发至 443） | 0.48 s | 37.56 Mbps |

数据非常直观：

### 1. BBR 有用，但解决不了 TCP 的结构性天花板

把拥塞控制从 CUBIC 换成 BBR，确实带来了 5 ~ 9 倍的提升；再配合 `/etc/sysctl.d/` 持久化 `fq` + `bbr`、将 TCP/UDP 收发缓冲区上限拉到 `16 MB`、关闭空闲慢启动（`tcp_slow_start_after_idle = 0`）并开启 `tcp_mtu_probing = 1`，TCP 链路明显更稳。但在晚高峰丢包环境下，单线程依然徘徊在 1.7 Mbps 附近，距离流畅 4K 仍有数量级差距。

### 2. Hysteria2 + UDP 端口跳跃才是跨洋普通线路的破局点

Hysteria2 基于 UDP/QUIC，并采用 **Brutal 拥塞控制**——它不再一见丢包就保守退让，而是在设定的带宽上限内按实测丢包率主动补发，直接吃满跨洋链路的可用带宽。

为了防止部分运营商对持续大流量的**单一 UDP 端口**触发限速（QoS），在服务端通过 `iptables` 将 `UDP 20000:50000` 重定向到 `443`（写成 systemd oneshot 服务保证重启不丢），并在客户端开启 `ports: 20000-50000` 定期换端口。实测下来，单线程吞吐稳定在 **37.56 Mbps**，首字节延迟压到 **0.48 s**。

更重要的是，Hysteria2 占用 `UDP 443`，与原有的 Xray（VLESS + REALITY，占用 `TCP 443`）**零冲突共存**。平时主力走 Hysteria2，遇到封锁 UDP 的公共 Wi-Fi 时一键切回 REALITY 兜底；GCP 防火墙只需放行 `TCP 443` 与 `UDP 443, 20000-50000`，SSH 入口收紧为仅允许 Google IAP 访问即可。

### 3. 顺手记录一个链式中转的踩坑

测试过程中曾尝试用第三方节点通过 `dialer-proxy` 中转到自建的 VLESS + REALITY，结果握手全报 `REALITY authentication failed`。排查后发现，原因是前置出口节点开启了 TLS SNI 嗅探与目标重写，把 REALITY 伪装的 SNI 域名直接改发给了真实目标站点，而非自建 VPS。既然 Hysteria2 直连已经跑出 37+ Mbps，彻底放弃第三方中转反而结构最干净、零额外依赖。

## 三、客户端分流、TUN 与 DNS 防泄露

服务端跑快之后，客户端如果直接「全局代理」，不仅国内应用绕路变慢，系统更新和网盘也会迅速吃光每月 200 GiB 的免费出站额度。

### 1. 理解 TUN 模式：它是「分拣员」，不是「全局代理」

很多人的顾虑是：开了 TUN 虚拟网卡，本地微信聊天和国内访问是不是也全绕去美国了？

并不会。普通系统代理只是给浏览器挂一张提示牌，终端（PowerShell、git、Python 等）和大量桌面软件根本不认它；**TUN 模式**是在操作系统里虚拟一张总控网卡，把所有软件的流量先统一收进内核的规则引擎，再由分流规则决定去向：

- **直连（DIRECT）**：局域网、`GEOSITE,cn`、`GEOIP,CN`，以及容易后台偷跑大流量的 **Apple、Microsoft / Windows 更新、Steam 国区**，全部走本地宽带直连，1 字节都不经过 VPS。
- **代理（PROXY）**：AI 服务与常见海外受限站点（`GEOSITE,gfw`、Google、YouTube、GitHub 等）走 Hysteria2。
- **兜底组（FINAL）**：默认设为 `DIRECT`，真正做到「未被拦截的走本地，受限的才走 VPS」；偶遇冷门海外小站打不开时，在策略组里点一下切到 `PROXY` 即可。

手机端（如 iOS 小火箭）底层本身就基于苹果的 NetworkExtension 虚拟网卡，打开开关即默认全系统 TUN 接管，只需把全局路由设为「配置」即可自动分流。

### 2. DNS 防泄露与关闭 IPv6

即便网页流量走了海外 VPS，如果客户端把国内 DoH（阿里、腾讯）和海外 DNS 混在同一个 `nameserver` 里并发查询，由于国内 DNS 响应更快，海外域名依然会落到国内运营商或公共 DNS 上解析，带来 DNS 污染或 CDN 分配错节点的问题。

干净的做法是在 Mihomo / Clash Verge 的全局 DNS 覆写里开启 `respect-rules: true`、移除本机运营商 `system` DNS，然后分池解析：

- `nameserver-policy` 将 `geosite:cn,private,apple-cn,microsoft@cn,steam@cn` 指定给阿里 / 腾讯 DoH，保证国内 CDN 精准且秒开；
- 默认 `nameserver` 只保留 `https://dns.google/dns-query` 与 `https://cloudflare-dns.com/dns-query`，并在分流规则顶部把这两个域名强制指向 `PROXY`，让所有海外域名解析全程加密经由 VPS 完成。

最后，在电脑端 Clash Verge 和手机端客户端里顺手**关闭 IPv6**，避免切换到支持 IPv6 的热点或宽带时，部分流量绕过 IPv4 代理直连泄露。

## 四、最后说一句关于 IP 属性的现实判断

自建独享 VPS 相比公共机场最大的优势，在于**出口固定、单人独享**，不会因为和几百人共用同一个出口而被连坐，也不会一天在几个国家之间来回跳动。

但也要保持清醒：Google Cloud 分配的依然是标准**云厂商数据中心 IP**（在各类 IP 情报库中明确标记为 `hosting: true`），并不是家庭住宅宽带 IP。网络层的固定静态 IP、分流、DNS 防泄露和关闭 IPv6，能保证你的链路本身干净、不漏、不乱跳，但它不是对抗严格平台风控的银弹。如果是为了长期稳定的开发调用，直接在同一套 GCP 账号里使用官方托管 API（如 Vertex AI），往往比在消费端账号上和风控博弈更省心。
